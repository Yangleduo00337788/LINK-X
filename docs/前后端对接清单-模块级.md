# LinkX 前后端对接清单（模块级）

> 目标：快速判断当前项目各功能模块是否已经接入真实后端，以及前端 UI 是否与后端能力对齐。
>
> 结论先行：**核心模块已真实对接，整体 UI 主路径已对齐，但仍存在少量半闭环、入口不全或状态联动未完全铺开的模块。**

---

## 一、判定标准

- **✅ 已对接且 UI 对齐**：前端已接真实后端，主流程可用，页面入口和交互闭环基本完整。
- **⚠️ 已对接但 UI 未完全对齐**：后端能力存在，前端也有部分接入，但页面入口、状态同步、异常态或细节交互仍需补齐。
- **🔧 后端已有 / 前端未完全接入**：后端存在能力或接口，前端尚未全面铺开。
- **❌ 未完成 / 空壳**：当前代码中未见完整可用的真实后端闭环。

## 三、确认度最高的真实后端对接

以下模块可以直接认为是**真实后端对接**，不是 mock：

1. **认证与 token 刷新**
2. **聊天主链路**
3. **好友 / 群聊 / 群公告**
4. **朋友圈 / 日历 / 笔记 / 收藏**
5. **文件上传 / 下载 / 秒传 / 分片上传**
6. **红包 / 余额 / 反馈**
7. **会议 / 通话信令**
8. **安全风控与审计**

这些模块在前端 `src/api/*.ts` 中都能看到明确的 HTTP 调用封装，且后端 `controller/service` 中有对应实现。

## 四、仍建议重点复查的 UI 对齐点

### 1. 消息回执体验

建议确认：
- 已读数是否在会话页、消息气泡、群聊页同步一致
- 退出重进、离线恢复后角标是否正确归零
- 群聊的已读人数是否始终与后端一致

### 2. 群管理入口

建议确认：
- 审批列表是否可见
- 禁言 / 批量管理 / 邀请策略是否在 UI 中完整暴露
- owner/admin/member 的不同权限是否真的体现在界面上

### 3. 通话与会议异常态

建议确认：
- 弱网时提示是否清晰
- 切换设备、重连、权限拒绝时是否有明确 UI
- 会议内的等候室、会中聊天、成员管理是否完整

### 4. 设置与通知

建议确认：
- 免打扰、通知开关、聚合规则是否一致展示
- 云端偏好是否与本地状态同步
- 设置项修改后是否立即反馈到 UI

### 5. 合规能力入口

建议确认：
- 数据导出、注销、审计日志是否有入口
- 文案是否与实际后端能力一致
- 空状态、确认弹窗、危险操作提示是否完整

---

## 五、综合判断

### 可以认为“已完成”的部分

- 核心聊天链路
- 登录鉴权与刷新
- 文件与消息上传
- 好友、群聊、朋友圈、日历、笔记、收藏
- 红包、余额、反馈
- 大部分设置与安全能力

### 可以认为“有后端，但 UI 仍需继续打磨”的部分

- 已读 / 送达回执展示
- 群管理高级操作入口
- 通话 / 会议的异常态与弱网体验
- 通知策略的前端表达
- 合规类页面入口与文案统一

### 不建议直接标成“未对接”的部分

这些模块更准确的定位是**半闭环**，不是空壳。

---

## 六、结论

如果你需要一句可以直接放到项目说明里的话，可以写成：

> LinkX 当前主体功能已接入真实后端，核心业务链路基本可用；前端 UI 已完成主路径对齐，但少量高级能力仍存在入口不全、状态联动不完整或异常态展示不足的问题。

---

## 七、建议的下一步

如果继续推进，最值得补的顺序是：

1. 消息已读 / 送达回执统一
2. 群管理高级入口补齐
3. 通话 / 会议异常态完善
4. 通知与偏好 UI 统一
5. 合规入口与文案统一
