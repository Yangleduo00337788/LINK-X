## 一、总体评价

整体统一性较好：主色（晴空蓝 `#12b7f5`）贯穿全站，左侧导航高亮态、窗控按钮、图标风格全站一致；设置类页面排版规整；深浅色主题 + 9 个主题色切换即时生效；空状态插画风格统一（LinkX 吉祥物系列）。

但存在 **1 个明确的布局 bug**（扩展页挤压 / 余额数字截断）、**2 个交互层级问题**，以及 **规范执行打折**（README 8.5 约定的 Design Token / 公共组件覆盖率不足）。

问题分级统计：

| 级别 | 数量 | 说明 |
|------|------|------|
| P0 功能/数据可见性受损 | 2 | 余额数字截断、扩展页挤压 |
| P1 交互缺陷 | 2 | 浮层层级、浮层关闭 |
| P2 规范一致性债务 | 4 | 硬编码颜色、空态/弹窗组件不统一等 |

## 二、P0 · 必须修复

### 2.1 扩展页打开时中间面板被挤压到不可用

**现象**：打开「友链 / 短视频」任一扩展标签后，中间内容列没有最小宽度约束，宽度被压缩到极限，出现大面积文字竖排与截断。实测各面板表现：

| 面板 | 具体表现 |
|------|----------|
| 文件 | 标题「文件」「我的网盘」竖成单字一行；表格「大小」列头被截成「大」 |
| 日历 | 「新建日程」按钮折成「新建日 / 程」两行；「今天」按钮文字竖排 |
| 收藏 | 「新建笔记」按钮竖排；搜索框只剩图标；「最新收藏 ▾」排序器折行 |
| 设置 | 「编辑资料」「账号信息」按钮文字折行；「LinkX ID」描述文字竖排成 4 行 |

**根因推测**：中间内容列（及扩展页）均为 flex 弹性收缩，无 `min-width` 下限；扩展页与内容列互相挤压。
**修复建议**：给中间内容列设置 `min-width`（如 360–420px），扩展页改为悬浮覆盖（overlay）或设置自身 `min-width` + 横向滚动。

### 2.2 余额页数字与按钮被截断（不开扩展页也可触发）

**现象**（见走查截图）：
- 顶部蓝色「可用余额」卡片中 **`¥ 0.00` 被截掉下半截**，金额只显示上半部分；
- 「充值」卡片内 ¥10 / ¥50 / ¥100 / ¥200 快捷金额按钮底部被切掉约一半；
- 窗口高度稍矮时即可复现，用户可能直接看错余额数据。

**修复建议**：检查余额页顶部卡片与充值卡片的固定高度 / `overflow: hidden` 设置，改为内容自适应或加 `overflow` 保护 + 最小高度。

## 三、P1 · 交互缺陷

### 3.1 浮层层级冲突：个人资料浮层压住弹窗

「个人资料」悬浮卡片打开时，再打开「添加好友/群聊」弹窗，浮层不会关闭，**遮挡弹窗标题与搜索结果区域**（实测搜索「O888212」的结果被浮层盖住左半部分）。

**修复建议**：打开任意模态弹窗时自动关闭 profile popover；或建立全局 z-index 层级约定（popover < modal）。

### 3.2 个人资料浮层无关闭控件

浮层没有 × 关闭按钮，只能依赖点击外部区域关闭，可发现性（discoverability）差。

**修复建议**：右上角加关闭按钮，或遵循「Esc 关闭 + 点击外部关闭」并保证后者可靠。

## 四、P2 · 规范一致性债务（对照 README 8.5）

README 8.5 明确约定：颜色间距优先 `var(--lx-*)`、按钮优先 `LxButton` / `.lx-btn`、公共组件统一从 `components/ui/` 导出。静态检查发现以下执行缺口：

### 4.1 硬编码颜色绕过 Design Token —— 约 58 个文件、427 处

写死 hex / rgba、未走 `--lx-*` 变量。重灾区（按数量排序）：

| 文件 | 处数 |
|------|------|
| `src/components/ShortVideoMainView.vue` | 86 |
| `src/components/chat/ConferenceRoomModal.vue` | 49 |
| `src/components/MomentsModal.vue` | 28 |
| `src/components/LoginView.vue` | 27 |
| `src/components/chat/IncomingCallModal.vue` | 16 |
| `src/components/chat/GroupCallModal.vue` | 13 |
| `src/components/RegisterView.vue`、`src/components/AiControlOverlay.vue` | 各 12 |
| `src/components/chat/VideoCallModal.vue`、`src/components/SliderCaptcha.vue` | 各 10 |

另 `src/views/ImageViewerView.vue`（9 处）等零星分布。**短视频 + 音视频通话系列约占问题总量一半**。

风险：切换主题色 / 深色模式时这些页面不会跟随，深色模式下易出现白底黑字的割裂页面。

### 4.2 空状态组件不统一

存在统一组件 `src/components/common/EmptyState.vue`，但**仅 7 个文件使用**（ChatList、ContactsPanel、OfficialNotifyPanel、MomentsModal、SystemNotifyPanel、ChatHistoryPage、OfficialNotifyDetailPage）；日历、余额、收藏、短视频系列等页面各自手写「暂无 XX」空态，另有自造的 `src/components/ops/DiscoverEmptyPane.vue`。

当前各空态视觉恰好相近，但属于巧合而非约束，改版时会逐渐发散。

### 4.3 弹窗 / 浮层三套并存

| 方式 | 使用量 |
|------|--------|
| 统一封装 `src/components/ui/LxModal.vue` | 10 个文件 |
| Naive UI 原生 `n-modal` / `n-drawer` | 4 个文件 |
| **自写 `position: fixed` 全屏浮层** | 25+ 个组件（另有 17 个文件自写 `modal-mask` / `modal-overlay` 类） |

典型：`MomentsModal.vue`、`MomentsComposerModal.vue`、`LockScreen.vue`、`LocationPickerPage.vue`、`AiControlOverlay.vue` 及 chat 下多个弹窗。这是 3.1 层级冲突的直接根源。

### 4.4 按钮未统一走公共组件

项目几乎不使用 Naive UI `n-button`（0 处），按钮全部是自定义 class 的原生 button（`lx-btn-*`、`account-picker-btn` 等）。主色 hex 本身没有绕过主题二次写死（0 处），但各自定义按钮 class 是否引用 `--lx-*` 变量需逐个确认，属结构性风险。

### 4.5 做得好的（无需处理）

- 内联样式纪律好：`style="font-size:…px"` 全项目 **0 处**，内联 padding/margin 仅 3 处；
- 主题系统完整：9 主题色 × 深浅色 × 跟随系统，切换即时生效且全站一致；
- 窗控按钮、导航高亮、图标风格全站统一；
- 注册 → 登录 → 搜索加好友全链路交互顺畅，反馈文案清晰；
- 空状态插画风格统一。
