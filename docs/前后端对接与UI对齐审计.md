# LinkX 前后端对接与 UI 对齐审计

> 审计时间：2026-07-26
>
> 结论先行：**项目核心功能已基本接入真实后端，但并非所有功能都做到完全闭环；前端 UI 也不是全部 1:1 对齐，仍存在少量半对接、入口不全或交互同步不完整的模块。**

---

## 一、审计范围

本次检查主要基于以下内容：

- 前端 `linkx-client/src/api/*`
- 前端主界面与核心组件 `linkx-client/src/components/*`
- 前端全局状态与启动链路 `linkx-client/src/AppRoot.vue`
- 后端 `linkx-server/src/main/java/com/linkx/server/controller/*`
- 项目说明文档 `README.md`、`docs/企业IM功能缺口清单.md`、`docs/整改优先级计划.md`

---

## 二、总体结论

### 1. 真实后端对接情况

**大部分核心业务已接真实后端。** 典型包括：

- 认证登录、Token 刷新、退出登录
- 聊天会话、消息历史、消息编辑/撤回/转发/引用
- 文件上传、分片上传、秒传、聊天附件
- 好友、群聊、群公告、群文件
- 朋友圈 / 动态、日历、笔记、收藏、红包、余额、反馈、通知
- 会议与通话相关接口
- WebSocket 实时消息链路

这说明当前项目不是 mock 前端，主体业务确实建立在 Spring Boot 后端之上。

### 2. UI 对齐情况

**主流程 UI 已对齐，但局部模块仍有差异。**

主要表现为：

- 某些后端能力存在，但前端入口、页面层级或状态联动不够完整
- 某些交互在 API 层已对接，但 UI 层没有把所有状态变化完整展示出来
- 部分企业化能力更偏“有能力，但未完全铺到所有页面”

---

## 三、已确认对接较完整的模块

### 1. 认证与会话基础链路

已包含：

- 登录 / 注册 / 刷新 token
- 设备信息上报
- 401 自动刷新与重试
- 安全存储与锁屏恢复

前端 `apiClient` 已统一封装鉴权与刷新逻辑，说明认证链路是真实接后端的，不是本地假数据。

### 2. 聊天主链路

已确认的真实后端对接包括：

- 会话列表
- 打开私聊
- 拉取消息历史
- 聊天文件上传
- 消息搜索
- 消息撤回 / 编辑 / 转发 / 引用
- 会话置顶 / 免打扰 / 重要标记 / 草稿
- 会话已读上报

### 3. 群聊与组织能力

后端控制器和前端 API 均能看到对应映射：

- 群创建 / 加群 / 邀请 / 成员管理
- 群公告
- 群文件 / 群资产
- 群通知相关页面与状态

### 4. 朋友圈、日历、笔记、收藏、红包、余额

这几类模块在前端都已拆出独立 API 与页面组件，且后端存在对应 Controller / Service / VO，说明不是单纯 UI 占位。

### 5. 通话与会议

项目已具备：

- 单聊通话
- 会议创建 / 加入 / 退出 / 静音 / 主持人转移
- WebRTC 信令和设备切换相关能力

但该部分的 UI 对齐程度需要单独看交互细节，见后文“半闭环模块”。

---

## 四、部分对接但 UI 未完全闭环的模块

以下模块不建议简单判断为“未对接”，更准确的说法是：**后端有能力，前端接入尚不完全**。

### 1. 已读 / 送达回执

- 后端具备回执相关能力
- 前端也已有 `markAsRead`、消息状态显示的基础
- 但是否在所有会话切换、滚动到底、离线补偿场景都稳定同步，还需要逐页核对

### 2. 群管理高级操作

- 后端有 owner / admin / member、禁言、入群审核、批量管理等能力
- 前端存在群设置和管理页面，但部分操作入口可能没有完整铺开
- 尤其是“申请列表 / 审批面板 / 批量管理”的 UI 对齐还应复查

### 3. 通话 / 会议弱网与设备切换

- 后端协议与服务侧能力是存在的
- 前端有 modal / store / policy 工具，但 UI 层的异常态、切设备、重连提示未必完全覆盖

### 4. 通知与偏好

- 后端偏好与通知链路已经存在
- 前端有设置页与本地通知桥接
- 但“系统通知、业务通知、免打扰、聚合规则”是否每一项都在 UI 中明确展示，需要逐项核对

### 5. 合规与安全类能力

- 数据导出、注销、审计、敏感词、黑名单等后端能力已存在
- 前端是否把这些能力全部做成可达页面，仍需核查

---

## 五、UI 对齐的整体判断

### 已对齐

- 登录 / 主界面 / 锁屏 / 主题切换
- 聊天主界面、会话列表、消息输入、消息气泡
- 联系人、收藏、文件、日历、朋友圈等主入口
- 设置中心的基础页签

### 可能存在差异

- 某些高级权限操作只有后端，没有完整 UI 入口
- 某些状态变化在接口上支持，但页面反馈不够完整
- 某些页面偏“功能已具备”，但视觉层级和交互细节还可以继续统一

---

## 六、风险点

1. **文档口径偏乐观**
   - README 与部分缺口文档都更倾向于“已完成”描述
   - 但从代码层面看，仍有一些功能属于半闭环或 UI 未完全铺开

2. **接口对接不等于体验闭环**
   - 有 API 不代表页面上所有异常态、空态、加载态都处理好了
   - 也不代表跨页状态同步一定一致

3. **部分能力依赖运行环境**
   - WebSocket、WebRTC、文件上传、通知等功能会受到后端、端口、浏览器权限、Electron 能力影响

---

## 七、建议的后续核对顺序

如果要继续把项目打磨成“前后端完全对齐”的状态，建议按下面顺序复查：

1. **聊天链路**
   - 已读 / 送达 / 离线补偿 / 搜索定位

2. **群管理链路**
   - 邀请、审批、禁言、成员权限、群公告

3. **通话与会议链路**
   - 异常态、弱网、设备切换、重连提示

4. **设置与通知链路**
   - 云端偏好、免打扰、聚合规则、系统通知表现

5. **合规与安全链路**
   - 数据导出、注销、审计、黑名单、敏感词

---

## 八、最终结论

**结论：LinkX 当前已经是一个“核心功能真实后端对接完成度较高”的项目，但仍存在少量模块的 UI/交互/状态同步缺口。**

如果按交付成熟度来描述，可以概括为：

- **核心主链路：基本真实对接完成**
- **企业化扩展：大体有后端，但 UI 铺开程度不完全一致**
- **整体 UI：主界面已对齐，局部功能仍需逐项复核**

> 因此，不建议把它描述为“所有功能都已完全对接并完全对齐”；更准确的说法是：**主体功能已对接真实后端，少数功能仍有半闭环与 UI 对齐问题。**
